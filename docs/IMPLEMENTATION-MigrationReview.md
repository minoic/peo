# 后端审查整改交付记录

日期：2026-10-25（Asia/Shanghai）。依据：[`REVIEW-MigrationReview.md`](./REVIEW-MigrationReview.md)。原报告保留为静态审查基线；本文件记录随后实现、迁移影响和运行证据。

## 范围与实现边界

本轮处理 R01–R16 及 D01–D05 的具体缺陷和契约差异。实现与相邻测试由 `development_assistant` 分工完成，主代理协调共享文件、审查并发与故障窗口、核对契约并执行组合验证。另有独立只读代理进行安全边界及兼容性复核。

保留 standalone MongoDB 部署方式，不要求切换副本集。资金和实例操作采用同文档原子更新、持久消费归属和恢复记录。真实数据库测试只使用各测试生成的独立数据库，Redis 测试只使用独立键，不修改业务数据库或执行全库清理。

可选设计建议（密码哈希升级、分页产品策略、多实例终端票据共享、批操作整体事务等）不视为已经实现的缺陷修复。现有 MD5 密码格式继续兼容；旧 Panel 账户权限和密码、旧明文密码缓存、未知归属孤儿服务器均不自动迁移或删除。

## 迁移与运维影响

- 启动时为空、过短或旧公开值的 JWT 密钥会被替换成持久随机值，原令牌需要重新登录。正常私有密钥保持不变；多个并发启动实例读取数据库中获胜的值。
- 新 Panel 镜像账户使用独立随机密码且 `root_admin=false`，不再因 PEO 管理员身份获得 Panel root。既有账户需由操作者另行盘点和轮换。
- Redis 撤销查询失败时，保护接口返回 `500 internal_error`，可选认证退回匿名，终端授权检查拒绝或关闭连接。普通冷却继续沿用 best-effort 策略。
- 设置候选先验证、后持久化、再发布；保存按进程串行。关联凭据使用同一快照，旧 Redis 客户端等待在途操作释放后关闭。跨应用进程的配置广播仍需部署侧协调。
- 未知图库动作改为验证错误；上传按实际字节计数限制。下载中断记录已传字节和错误，并中止传输，避免输出一个正常结束的残缺文件。
- 上传取消会中止管道和上游请求，但 Panel/Wings 已收到的内容可能留下部分文件或已覆盖原文件；当前没有可靠的上游写入回滚，不能将请求取消视为文件内容已恢复。
- 新建充值记录保存 Alipay 应用绑定。没有 `paymentAppId` 的历史未结算记录拒绝自动入账和恢复，必须先与商户流水核对；不得直接补状态后重放通知。
- 余额操作回执永久保留，每用户当前上限为 10,000 条，达到上限后拒绝新变更。不能按年龄直接删除回执，否则旧工作者或重放请求可能再次扣款/入账；上线前需安排保留防重放能力的归档方案。
- 开服先持久化意图并原子扣款，再调用 Panel；Panel 失败时金额保留在待恢复操作中，不自动退款或允许另一个支付尝试。只有明确未扣款的失败允许创建新尝试。后台恢复每分钟执行；这改变了此前内存补偿的失败表现。
- 创建和删除操作绑定原 Panel 地址与凭据指纹。配置变化时暂停未完成的外部操作；恢复原凭据或人工核对后处理，不能直接改绑定来指向另一个 Panel。已确认上游删除的记录仍可完成本地清理。

## 逐项整改

| 编号 | 实现与验收重点 |
|---|---|
| R01 | 拒绝公开、空或过短 JWT 密钥；启动随机生成并以数据库原子竞争结果为准。 |
| R02 | Alipay 结算领取与余额操作回执分离但可恢复，重复通知只入账一次。 |
| R03 | 兑换码原子领取，领取用户和操作固定；过期清理保留待完成的消费权。 |
| R04 | 余额条件扣减与操作回执在同一文档更新，防止并发超支及重复扣款。 |
| R05 | 续费、删除审批及实际删除共享状态、日期和待续费条件；删除领取后禁止续费。 |
| R06 | 首个管理员账号与唯一 bootstrap 标记原子插入；新 Panel 账号随机密码、非 root。 |
| R07 | 撤销查询区分故障与未撤销；保护接口和终端授权故障时拒绝访问。 |
| R08 | 原子领取校验过期与商品；续费先持久化目标日期及操作，取消结果可恢复。 |
| R09 | 订单创建和实例删除持久化阶段、固定目标及工作者租约；响应丢失后查询稳定外部 ID，再恢复本地状态。 |
| R10 | cron 包装实际同步任务，启动任务和周期任务共享防重入；停止有统一期限。 |
| R11 | Minecraft 探测使用 context、连接期限和取消关闭，限制包长，避免脱离请求的 IO。 |
| R12 | 上传按真实读取字节限额，包括未知 Content-Length；取消/错误关闭管道并传播。 |
| R13 | 图库仅接受明确的 pass/delete，未知动作不访问删除路径。 |
| R14 | 下载复制错误记录字节并中断 HTTP 传输；恢复中间件保留中断语义。 |
| R15 | 保存串行合并、持久化后发布；关联客户端单快照构造，缓存按 Panel 身份隔离，旧 Redis 客户端排空。 |
| R16 | 精确金额和应用/交易绑定；安全随机源错误返回调用者，不降级到非安全随机。 |
| D01–D05、C2 | 同步 API、路由、架构和数据契约；加强 AST 层边界检查与更新时间测试，CI 配置真实 MongoDB/Redis 及 race 检测。 |

独立复核补充修复了兑换码领取响应不确定时的错误释放、取消回执落库后恢复卡死、实际删除遗漏续费条件，以及 bootstrap 崩溃窗口和配置切换后的旧 Egg 缓存问题。

## 验证记录

基线：使用仓库内缓存后，修改前 `go test ./...` 全部通过。本机依赖已确认：MongoDB 7.0.43 standalone（`setName=null`），Redis `PING` 返回 `PONG`。

最终工作区验证（Go 1.27.1，Windows，本地独立测试数据库/键）：

| 检查 | 结果 |
|---|---|
| `go build ./...` | 通过；使用进程级 Git safe.directory 配置，未修改全局 Git 设置。 |
| `go vet ./...` | 通过。 |
| `go mod tidy -diff`、`gofmt -l ./cmd ./internal` | 无差异、无未格式化文件。HTTP/2 测试使已有 `golang.org/x/net` 转为直接依赖，版本不变。 |
| `go test -count=1 -timeout 120s ./...` | 全部通过，启用真实 MongoDB/Redis 集成测试。 |
| `go test -race -count=1 -timeout 180s ./...` | 全部通过，启用同样的真实依赖；Windows 使用 MinGW GCC 与 CGO。 |

测试环境变量为 `PEO_TEST_MONGO_URI` 和 `PEO_TEST_REDIS_ADDR`；未设置时相关集成测试会跳过，普通无环境变量的通过结果不能替代上述验证。本轮使用 `mongodb://127.0.0.1:27017/?serverSelectionTimeoutMS=2000` 和 `127.0.0.1:6379`。

验证中发现并修正了探测取消写入路径的错误归类、bootstrap 测试唯一字段冲突，以及新恢复测试的大小写重复配置键；以上最终测试均在修正后重新执行。真实 Panel/Wings、Alipay 商户通知、SMTP 和浏览器业务回归尚不能用 mock 或数据库测试替代。

主要回归证据：

| 层次 | 覆盖 |
